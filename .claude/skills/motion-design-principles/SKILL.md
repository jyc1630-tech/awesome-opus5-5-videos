# 모션 디자인 원칙

원칙 5개 + 세부 규칙 20개. 수치는 추정 기준이며, 상충 시 **원칙 > 세부 규칙** 순으로 판단함.
출처: @thedalbee 「모션 디자인 원칙」 인포그래픽 정리.

## 사용 방법

1. **기획 단계**: 대본을 문장(슬롯) 단위로 나누고, 원칙 01·05로 씬/클립을 배정함.
2. **제작 단계**: 원칙 02~04와 세부 규칙을 기준으로 움직임·글자·전환을 결정함.
3. **검수 단계**: 하단 「검수 체크리스트」로 씬별 위배 / 반쯤 위배 / 지킴을 판정해 보고함.

## Ⅰ. 핵심 원칙 5개

### 01. 씬 하나에 도식 하나
- 씬 하나 = 설명 도식 하나. 평균 **15~20초**.
- 슬롯(자막 한 줄)은 도식에 칸이나 요소가 **하나 더해지는** 시각임.
- 슬롯마다 새 장식 사물을 띄우지 않음.

### 02. 변할 때만 움직인다
- 등장하거나 도식의 의미 있는 상태가 바뀔 때만 움직이고, 끝나면 정지함.
- **금지**: 흔들림, 떠다님, 채움용 줌, 씬 안 바탕 교체.
- 한 화면 덩어리 **7개 이하**. 8번째 전에 묶음을 접음.
- **25초 초과 + 소주제 2개**이면 씬을 나눔.

### 03. 글자는 최후 수단
- 그릴 수 있는 말은 사물, 로고, 양, 표정으로 바꿈.
- 비교 → 막대, 변화 → 선, 비율 → 10칸 중 N칸, 순서 → 화살표.
- 자막을 화면 글자로 되풀이하지 않음.

### 04. 전환은 씬 경계에만
- 트랜지션과 효과음은 **씬 경계에만** 사용.
- 효과음은 **분당 15개 이하**.
- 같은 효과음 파일을 **30초 안에 재사용하지 않음**.

### 05. 문장 하나에 클립 하나
- 스톡은 직관적인 말, 사물을 가리키는 말에 사용.
- 문장 하나에 클립 하나. 클립 하나는 **3초 이상** 화면에 둠.

## Ⅱ. 세부 규칙 20개

### 가. 화면 밀도·리듬
1. **화면이 정신없으면 실패** — 씬마다 움직이는 요소와 강조 수를 줄임. 녹화 구간은 확대와 강조를 하나씩만 검.
2. **사건이 끝나면 바로 다음** — 정적인 화면을 오래 두지 않음. 코드는 왼쪽, 그 코드가 만든 결과는 오른쪽에 나란히. 첫 장면을 꾸며낸 연출로 열지 않음.
3. **씬 정원** — 주인공 사물 1개, 보조 1~2개, 글자 덩어리 1개(숫자 하나 또는 6어절). 넘치면 씬을 나눔. 크레딧은 평면 칩 대신 돌탑·카지노 칩 같은 실물로 표현.
4. **기준점과 연속성** — 기준점은 고정하고 바뀌는 대상과 이름표만 움직임. 관계를 설명하지 않는 움직임은 즉시 교체. 페이드 금지.

### 나. 화면과 말의 정합
5. **실사가 있으면 무조건 실사** — GitHub, X, 공식 사이트, 제품 화면을 직접 캡처. 그 위에서 카메라를 앞뒤로 움직이고, 말이 가리키는 곳(예: 별 숫자)을 확대.
6. **화면은 말보다 먼저 나가지 않는다** — 아직 말하지 않은 대상을 미리 보여 주지 않음. 낯선 개념은 화면이 정의를 보여 줌. 자막은 말이 시작하는 프레임에 뜸.
7. **화면은 말하는 대상을 보여 준다** — "앱을 만들었다" 슬롯에는 앱 화면. 터미널과 코드는 과정을 말하는 슬롯에만.
8. **어려운 개념은 멈춘 화면** — 낯선 개념은 움직임을 멈추고 한 화면에 정의를 그림. 쉬운 관계는 화살표 한 번으로 끝냄.

### 다. 화면 녹화
9. **녹화는 확대와 원문 강조** — 말하는 자리를 확대. 글자·버튼은 각진 상자, 물체·인물은 화살표로 짚음. 움직이는 물체를 상자로 따라가지 않음. 장식·새 사물·화면 글자는 넣지 않음.
10. **녹화에서 녹화로는 즉시 교체** — R씬→R씬 경계에는 트랜지션을 걸지 않음(하드 컷). 자동 검사 스크립트(예: `boundary_transition_gate.py`)로 차단.
13. **메인 화면은 화면 녹화가 기본** — 실제 화면을 그대로 보여 줌. 모션 그래픽은 녹화로 못 보여 주는 자리에만 넣고 영상 전체를 덮지 않음.
15. **글 보며 말한 곳은 모션 씬** — X 글을 띄워 놓고 풀어 말한 구간은 녹화를 1프레임도 쓰지 않음. 실제 시연한 녹화만 남김. X 아티클 캡처도 모션으로 바꿈.
16. **시연 녹화 속 개인 정보는 가린다** — 사용자 이름 경로, 사이드바, Finder 목록, 할 일, 세션 ID, 메모 화면 등. 확대 범위로 화면 밖으로 빼고, 안 되면 종이 띠로 덮음.

### 라. 효과·스타일
11. **눈에 띄는 효과는 한두 번만** — 같은 효과는 영상 전체에서 1~2회. 도입부(첫 3분) WebGL은 배경 무늬로 끝내지 말고 씬마다 다른 움직임을 넣음.
12. **쓰지 않는 것** — 흑백 처리, 리소그래피 질감, 페이드·투명도 전환, 평면 칩 크레딧. 시선은 크기, 위치, 강조 상자, 어둡게 깐 판으로 모음.
14. **실물 사이에 생성 모션** — 실물이 없는 개념·비유·사람 행동은 무드보드 캐릭터와 사물을 이미지 생성으로 만들어 움직임. 같은 모양 스크린샷이 이어지면 모션을 더함.
20. **간단한 사물은 3D 소품 라이브러리 먼저** — 크림 돌판, 돌 비석, 유리 명패, 유리 막대, 10칸 판, 카지노 칩 등. 없을 때만 이미지 생성. 회차 프로젝트에는 심볼릭 링크로 불러옴.

### 마. 레이아웃·구조
17. **세로 화면 위아래는 데드스페이스** — 1080×1920에서 1:1 영상은 가운데 y 420~1500. 제목 y 343, 자막 y 1285, 출처 y 1537~1575. 그 위아래는 비움.
18. **도식은 도해 원칙 4단계로** — ① 메시지 한 문장 → ② 무엇에 답하는지 → ③ 도해 사전에서 뼈대 선택 → ④ 설계 규칙 6개로 점검. 위배 / 반쯤 위배 / 지킴으로 판정.
19. **루프 영상은 끊김 없이** — 끝 프레임이 첫 프레임으로 이어짐. 카메라 두 대는 바로 컷, 예고 움직임은 한 방향, 컷은 사건 프레임에 0프레임 오차. 등장 이징은 `easeOutExpo`.

## Ⅲ. 수치 기준 요약

| 항목 | 기준 |
|---|---|
| 씬 길이 | 평균 15~20초, 25초 초과 + 소주제 2개면 분할 |
| 한 화면 덩어리 | 7개 이하 |
| 씬 정원 | 주인공 1 · 보조 1~2 · 글자 덩어리 1(숫자 1개 또는 6어절) |
| 효과음 | 분당 15개 이하, 동일 파일 30초 내 재사용 금지 |
| 스톡 클립 | 문장당 1개, 3초 이상 |
| 눈에 띄는 효과 | 영상 전체 1~2회 |
| 세로(1080×1920) | 본 영상 y 420~1500 · 제목 y 343 · 자막 y 1285 · 출처 y 1537~1575 |
| 등장 이징 | easeOutExpo |
| 루프 컷 오차 | 0프레임 |

## Ⅳ. 검수 체크리스트

씬마다 아래 항목을 **지킴 / 반쯤 위배 / 위배**로 판정하고, 위배 항목은 수정안을 함께 제시함.

- [ ] 씬에 도식이 하나뿐인가, 15~20초 범위인가 (원칙 01)
- [ ] 상태 변화 없는 움직임(흔들림·떠다님·채움 줌)이 없는가 (원칙 02)
- [ ] 화면 덩어리 7개 이하, 씬 정원 초과 없는가 (원칙 02, 규칙 3)
- [ ] 그릴 수 있는 말을 글자로 띄우지 않았는가, 자막 중복 없는가 (원칙 03)
- [ ] 트랜지션·효과음이 씬 경계에만 있는가, 분당 15개 이하인가 (원칙 04)
- [ ] R씬→R씬 경계가 하드 컷인가 (규칙 10)
- [ ] 화면이 말보다 앞서 나가지 않는가, 자막 싱크가 맞는가 (규칙 6)
- [ ] 페이드·투명도 전환, 흑백, 평면 칩을 쓰지 않았는가 (규칙 4, 12)
- [ ] 개인 정보가 노출되지 않는가 (규칙 16)
- [ ] 세로 영상 안전 영역을 지켰는가 (규칙 17)
