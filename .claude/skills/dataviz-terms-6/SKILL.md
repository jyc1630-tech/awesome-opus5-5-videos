# 데이터 시각화 용어 6가지와 토큰 절약 프롬프트

정확한 차트 이름을 쓰면 긴 설명 없이도 원하는 시각화를 한 문장으로 요청할 수 있다.
사용자의 자료와 목적을 듣고 아래 6가지 중 맞는 것을 고른 뒤, 차트를 바로 만들거나 요청 문장을 써 준다.

## 고르는 기준 (한눈에)

| 보여주고 싶은 것 | 차트 |
|---|---|
| 여러 단계를 거치며 나뉘고 이동하는 흐름·양 | 1. 생키 다이어그램 |
| 목표 대비 실적(두 값 겹쳐 비교) | 2. 레이어드 바 차트 |
| 시간에 따른 항목별 순위 변화 | 3. 범프 차트 |
| 날짜별 많고 적음(활동량) | 4. 캘린더 히트맵 |
| 표 안에서 수치와 크기를 함께 비교 | 5. 테이블 바 차트 |
| 시간이 지나며 남아 있는 비율(유지율) | 6. 리텐션 커브 |

## 1. 생키 다이어그램 (Sankey Diagram)
- 용도: 데이터가 여러 단계를 거치며 어떻게 이동하고 나뉘는지 흐름의 굵기로 표시
- 프롬프트: "검색과 소셜에서 유입된 사용자가 방문, 가입, 결제까지 어떻게 이동하는지 생키 다이어그램으로 보여줘."

## 2. 레이어드 바 차트 (Layered Bar Chart)
- 용도: 두 개 이상의 막대를 겹쳐 목표와 실적처럼 비교할 수치를 한눈에 표시
- 프롬프트: "월별 매출 목표와 실제 매출을 레이어드 바 차트로 비교해줘. 목표는 회색, 실적은 보라색 막대로 표시해줘."

## 3. 범프 차트 (Bump Chart)
- 용도: 시간이 지남에 따라 항목별 순위가 어떻게 바뀌는지 표시
- 프롬프트: "의류, 뷰티, 생활 카테고리의 월별 판매 순위 변화를 범프 차트로 보여줘."

## 4. 캘린더 히트맵 (Calendar Heatmap)
- 용도: 날짜별 데이터의 크기를 색상으로 표현해 활동이 많거나 적은 날을 한눈에 표시
- 프롬프트: "최근 12주 동안의 일별 사용자 접속량을 캘린더 히트맵으로 보여줘. 접속이 많을수록 색상을 진하게 표시해줘."

## 5. 테이블 바 차트 (Table Bar Chart)
- 용도: 표 안에 수치와 작은 막대를 함께 표시해 항목별 크기를 빠르게 비교
- 프롬프트: "고객별 매출을 표로 보여주고, 각 행에 매출액에 비례하는 테이블 바 차트를 추가해줘."

## 6. 리텐션 커브 (Retention Curve)
- 용도: 시간이 지남에 따라 사용자가 얼마나 다시 방문하거나 서비스를 이용하는지 표시
- 프롬프트: "가입한 사용자의 주차별 재방문율을 리텐션 커브로 보여줘. 가로축은 가입 후 주차, 세로축은 사용자 유지율로 표시해줘."

## 프롬프트 작성 공식 (토큰 절약)
`[무엇을/누구의] + [어떤 기준으로] + [차트 이름]으로 보여줘. + (선택) [축·색상·강조 조건]`
- 차트 이름을 정확히 쓰고, 모양을 길게 묘사하지 않는다.
- 꼭 필요한 조건(축, 색, 강조)만 한 문장으로 덧붙인다.

## 교육행정 활용 예시
- 생키: "학교급별 신청 교원이 연수 신청→이수→현장 적용까지 어떻게 이동하는지 생키 다이어그램으로 보여줘."
- 레이어드 바: "사업별 예산 배정액과 집행액을 레이어드 바 차트로 비교해줘. 배정은 회색, 집행은 파란색으로."
- 범프: "지원청별 연수 이수율 순위의 월별 변화를 범프 차트로 보여줘."
- 캘린더 히트맵: "최근 12주 원격연수 플랫폼 일별 접속자 수를 캘린더 히트맵으로 보여줘."
- 테이블 바: "학교별 신청 인원을 표로 보여주고, 각 행에 인원에 비례하는 테이블 바 차트를 추가해줘."
- 리텐션 커브: "연수 개강 후 주차별 참여 유지율을 리텐션 커브로 보여줘."

## 실행 원칙
- 사용자가 자료를 주면 차트를 바로 만든다. 자료가 없으면 요청 문장만 써 주거나 예시 데이터로 만든다(예시임을 밝힌다).
- 차트를 실제로 그릴 때는 dataviz 또는 ztd-charts 스킬 지침을 함께 따른다.
- 6가지로 맞지 않는 자료는 chart-type-guide 스킬로 다른 차트를 고른다.
